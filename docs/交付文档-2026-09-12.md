## 一、技术文档

### 1.1 架构基线（本次交付沿用）

- **后端**：Vercel Serverless 单函数架构（`api/index.js` 统一分发 → `server/` 目录路由），零 Express 依赖，冷启动最小化
- **存储**：Upstash Redis / Vercel KV（REST 协议），未配置时自动降级内存演示模式；业务层仅依赖 `server/_lib/storage.js` 适配器接口
- **认证**：JWT 无状态 Access Token（15 分钟）+ 可吊销 Refresh Token（7 天，KV 存储轮换）；密码为前端 `sha256(password::flwb::v1)` 传输、服务端 bcrypt 落库
- **前端**：Vue 3 + Vite 双应用（`apps/admin-web` 医护端 / `apps/patient-h5` 患者端），Element Plus + ECharts

### 1.2 任务2：患者随访提醒修复与优化

**问题排查流程（已内建为可观测能力）**：

```
提醒未送达
 ├─ 服务端：提醒发送日志（/api/v1/followups/remind-log）→ 按 日/状态 筛选定位
 │    ├─ status=skipped → 患者未绑定账号（userId 为空），需引导注册/建档绑定
 │    ├─ status=failed/partial → 查看渠道级 detail（inapp/sms 各自 error 与时间戳）
 │    └─ retryCount/retryAt → 是否已进入自动重试队列
 └─ 客户端：患者端消息中心未读数 + msg:unread 计数比对，确认接收侧正常
```

**通知服务层 `server/_lib/notify.js`**：

- `sendReminder`：统一发送入口，逐渠道记录 `{status, mid?, error?, ts}` 明细，持久化 `notify:log:${date}` 列表 + `notify:item:${id}` 明细
- 状态机：`pending → sent | partial | failed | skipped`，失败自动入重试队列（30 秒 / 5 分钟 / 30 分钟，最多 3 次）
- 超过重试上限 → 自动向主管医生推送告警站内信
- `processRetryQueue`：幂等补发（查看日志时机会式触发，上限 50 条/次）；`resendNotify`：手动重发

**API**：`GET/POST /api/v1/followups/remind-log`（staff；GET 查询+统计，POST 手动重发）

**前端**：`Followup.vue`「📨 提醒发送日志」弹窗——日期/状态筛选、送达/失败/跳过/待重试统计、失败项一键重发

### 1.3 任务3：质量看板功能增强

- 原「业务趋势（按天）」聚合图拆分为 **4 个独立分析图表**：新增建档量 / 随访执行量 / 失访量 / 高危新增（`Quality.vue` + `TrendChart.vue`）
- 图表类型切换：折线图 / 柱状图 / 面积图（3 种），ECharts 按需重建 option
- 交互：悬停数值详情、时间范围选择（7/30/90/180 天）、风险维度筛选联动
- 数据导出：CSV（UTF-8 BOM，Excel 直开）与 Excel（.xls 表格流）双格式，前端生成零后端改动（`apps/admin-web/src/utils/export.js`）

### 1.5 任务5：患者数据一致性与同步机制

**患者唯一标识匹配 `server/_lib/patient-match.js`**：

- 匹配优先级：**身份证号 > 手机号 >（可选）姓名+出生日期候选**
- 索引：`patient:index:idcard:${id}` / `patient:index:phone:${p}` → patientId
- 兜底：索引缺失时全量扫描患者档案（上限 1000 条），命中即回填索引，兼容存量数据

**双向绑定（杜绝同一自然人重复建档）**：

- 医生建档（`registry/index.js`）：建档前先匹配，命中且属其他医生管理 → 409 引导转介；命中本人管理 → `bindExistingPatient` 复用账号（`accountExisted=true`）并更新病历版本
- 患者自注册（`auth/login.js` register 模式）：注册时匹配医生已建档案 → 绑定既有档案（补齐体征、随访排期），推送关联成功通知

**实时同步与列表稳定**：

- `Patients.vue`：30 秒可开关自动刷新；轮询封装为幂等 `startPolling/stopPolling`，配齐 `onActivated/onDeactivated`（keep-alive 安全）与 `onBeforeUnmount`
- 「患者不存在」错误统一为含引导文案（`patient-access.js`）：提示返回「专病建档」页完成一站式建档

### 1.6 任务6：患者登录功能稳定性（本次交付重点）

#### 1.6.1 登录错误细化（告别“账号或密码错误”一刀切）

| 场景 | HTTP/BizCode | 提示文案 |
|---|---|---|
| 账号不存在 | 404 / 40401 | 账号不存在，请核对后重试，或先注册建档 |
| 密码错误 | 401 / 40102 | 密码错误，还可尝试 N 次（超出后账号将临时锁定） |
| 触发锁定 | 401 / 40103 | 密码连续错误 5 次，账号已锁定 15 分钟；可短信验证码登录或重置密码立即解锁 |
| 锁定期间登录 | 429 / 40103 | 失败次数过多，账号已临时锁定（约剩 X 分钟）… |
| 账户停用 | 403 / 40301 | 该账户已被停用，请联系管理员处理 |
| 短信验证码错误 | 422 / 42202 | 验证码错误或已过期 |

> 说明：具体化提示按要求实现（利于患者自助排障）；暴力破解风险由「失败锁定 + 登录限流 10 次/分/IP」对冲。

#### 1.6.2 账号锁定与自助解锁（`server/_lib/login-security.js`）

- 策略：15 分钟窗口内密码连续失败 **5 次** → 锁定 **15 分钟**（按登录标识小写归一计数）
- 自助解锁双通道：**短信验证码登录**（不受密码锁影响）/ **重置密码**（成功即解锁）
- 锁定事件输出 `logger.warn('login.lock')`，可对接平台告警

#### 1.6.3 登录日志与异常登录检测

- 全量记录（成功/失败/锁定/重置），字段：时间、账号、角色、方式（password/sms/register/reset）、状态、原因、IP、UA（截断 120 字符）
- 存储：`login:log:${date}` 按日列表，保留 500 条/日
- 查询 API：`GET /api/v1/auth/login-logs`（staff；`date`/`status` 参数），返回脱敏明细 + 统计（成功/失败/锁定/重置计数、**失败集中账号**（疑似暴力破解）、**多账号同 IP**（疑似撞库））
- 医护端新页面：「登录日志」（`/login-logs`，doctor 角色菜单）——日期/状态筛选、统计条、异常信号告警横幅、账号脱敏展示

#### 1.6.4 密码找回/重置流程

**后端 `POST /api/v1/auth/reset-password`**（public，限流 5 次/分/IP）：

```
输入 {phone, code, newPasswordHash}
 1. 短信验证码校验（全部校验通过后才消费，无效提交不烧码）
 2. 按手机号定位账号（未注册 → 404 引导）
 3. 新旧密码同密拦截（42203）
 4. bcrypt 改密 + 立即解锁（清失败计数与锁定标记）
 5. 吊销该用户全部会话（旧 Refresh Token 即刻失效，Access 15 分钟内自然过期）
 6. 安全通知（站内信：重置时间 + 非本人操作提醒）+ 审计 + 登录日志
 7. 自动登录（验证码已证明手机归属，直接签发新令牌）
```

**会话批量吊销支撑（`server/_lib/auth.js`）**：Refresh Token 增加按用户索引 `refresh:index:uid:${uid}`（签发 sadd / 轮换 srem+sadd / 登出 srem），`revokeUserSessions(uid)` 一次清空。

**患者端 `Login.vue`**：密码登录区「忘记密码？手机验证码重置」入口 → 重置表单（手机号+验证码+新密码+确认，客户端校验一致性与最小长度）→ 成功自动进入首页。

## 三、用户操作说明

### 3.1 医护端（/admin）

**登录日志（新）**
1. 医生登录 → 侧边栏「登录日志」
2. 顶部选择日期 / 状态（成功、失败、锁定、密码重置）筛选；右上角刷新
3. 页面顶部统计条查看当日总量与分布；出现橙色告警横幅时（失败集中 / 多账号同 IP），建议电话核实患者或提醒患者修改密码
4. 账号列已脱敏（如 `138****0001`）；「设备(UA)」列悬停可看完整标识

**随访提醒排障**
1. 「随访管理」→「📨 提醒发送日志」
2. 按日期与状态（已送达/发送失败/部分成功/已跳过）筛选
3. 失败/部分成功行点「重发」；`已跳过` 表示患者未绑定账号——引导其在患者端注册（同手机号将自动关联档案）

**质量看板**
- 4 张趋势图各自独立切换 折线/柱状/面积；顶部选时间范围（7/30/90/180 天）
- 每张图右上「导出」→ CSV 或 Excel（Excel 直接双击打开）

**宣教模板管理**
1. 「宣教推送」→「模板管理」Tab →「新建模板」
2. 填写标题/分类/标签/HTML 正文 → 保存；列表支持按分类与标签检索
3. 启停开关控制模板是否出现在推送选择器；编辑自动升级版本号
4. 回「推送」Tab 即可向患者批量下发自定义模板

**患者列表实时性**
- 患者管理页默认开启 30 秒自动刷新（右上开关可关）；建档/注册数据变化后无需手动刷新

### 3.2 患者端（/patient）

**登录遇到问题时**
- 密码输错：提示剩余尝试次数（5 次后锁定 15 分钟）
- 忘记密码：密码登录区点「忘记密码？手机验证码重置」→ 输入注册手机号获取验证码 → 设置新密码（两次一致、至少 6 位）→ 重置成功自动登录（其他设备会被强制退出）
- 账号被锁：可立即改用「验证码登录」，或直接走重置密码解锁
- 收不到短信：演示模式验证码会直接显示在页面（生产环境需配置 SMS_KEY）

## 四、遗留事项与生产建议

1. **短信服务商接入**：`server/auth/sms.js` 预留调用点，配置 `SMS_KEY` 环境变量后自动关闭 demoCode 直返
2. **JWT_SECRET**：生产部署必须设置强随机密钥（当前为开发默认值）
3. **登录日志保留**：按日 500 条上限，但历史日期键无 TTL；建议后续在 `cron/followup-remind` 的清理任务中追加“删除 30 天前的 `login:log:*`”
4. **管理员手动解锁**：当前锁定 15 分钟自动解除，患者可自助解锁；如需管理员强制解锁入口可在登录日志页扩展（`unlock(db, key)` 已就绪）
5. **账户停用状态**：登录链路已支持 `user.status === 'disabled'` 拦截，管理端停用/启用操作界面待后续需求
